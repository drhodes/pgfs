    Reference: Dual-Interface Architecture¶

    Status: Planned, not implemented

    The PgfsBackend trait, its error mapping and an inode-keyed implementation on Db exist and are unit-tested, but the FUSE layer does not route through them yet. RemoteBackend is a stub, the pgrx engine and the io_uring transport are at the design stage, and there is no --backend option.

    pgfs features a Dual-Interface Storage Architecture providing a sub-100µs Local In-Process Engine (pgrx + zero SQL parsing + io_uring zero copy) and a scalable Remote Async Network Engine (tokio-postgres + pipelining).

    Specification requirements¶

    DualInterfaceArchitecture is built from these requirement classes. Each is declared in spec/ and listed in the feature's deps.

    PgfsBackendTraitReq

    spec.optimize.PgfsBackendTraitReq

    A unified async PgfsBackend trait decouples the FUSE driver (src/fs.rs) from storage engine implementations.

    Technical Details:

    • Exposes async methods: lookup, getattr, setattr, readdir, mkdir, rmdir, create, unlink, rename, read_block, write_block, truncate_blocks.
    • Maps database failures into structured StorageError variants (NotFound, AlreadyExists, NotEmpty, InvalidArgument, DatabaseError, IoError).
    • Enables pluggable backend switching (LocalBackend vs RemoteBackend) at daemon startup.
    LocalPgrxEngineReq

    spec.optimize.LocalPgrxEngineReq

    The local storage engine (LocalBackend) operates inside PostgreSQL as a pgrx background worker (pg_bgworker) using pre-compiled SPI plans and binary Datums to achieve Zero SQL Text Parsing on the hot path.

    Technical Details:

    • Runs inside PostgreSQL postmaster via RegisterBackgroundWorker.
    • Pre-compiles statement handles (SPIPlanPtr) during worker startup using SPI_prepare.
    • Receives binary operation descriptors over a lockless shared-memory ring buffer (shm_mq) from the standalone FUSE daemon.
    • Executes SPI_execute_plan using raw binary Datum values (Int64GetDatum, Int32GetDatum), bypassing SQL text formatting, parsing, and planning entirely.
    IoUringBufferRingReq

    spec.optimize.IoUringBufferRingReq

    Where supported by kernel (Linux 6.9+ fuse-io_uring), pgfs utilizes io_uring Submission/Completion queues paired with pre-registered shared memory buffer rings (IORING_OP_PROVIDE_BUFFERS) for zero-copy data flow.

    Technical Details:

    • Replaces /dev/fuse read()/write() syscalls with asynchronous io_uring SQ/CQ rings.
    • Maps POSIX shared memory buffers (shm_mq) as pre-registered io_uring buffer rings.
    • Kernel VFS places incoming file block payloads directly into shared memory buffers accessible by the pgrx worker, enabling end-to-end zero-copy data flow into PostgreSQL SharedBuffers.
    RemoteAsyncBackendReq

    spec.optimize.RemoteAsyncBackendReq

    The remote storage engine (RemoteBackend) operates out-of-process using fuse3 and tokio-postgres over TCP or Unix sockets.

    Technical Details:

    • Uses fuse3 async FUSE bindings and tokio-postgres connection pools (bb8).
    • Implements query pipelining over single connection handles using query_raw.
    • Integrates atomic ReplicaFreshnessCache for read-replica traffic routing.
